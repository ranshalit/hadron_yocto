# Hadron L4T R36.5.0 Upgrade Design

## Goal

Align Hadron NGX012's Yocto image with Lumen's NVIDIA platform baseline at
L4T R36.5.0 / JetPack 6.2.2, including the host image's declared NVIDIA runtime
libraries, while retaining Hadron's board-specific configuration.

This does not claim parity with libraries packaged inside Lumen application
containers; those container images and their complete dependency manifests are
not in the Lumen repository.

## Scope

- Pin Hadron's `meta-tegra` to Lumen's exact revision:
  `d2613418be82dd95733824a0839c185ec0e02f2d`.
- Add the NVIDIA packages declared by Lumen's image recipe:
  `tegra-libraries-core`, `tegra-libraries-eglcore`,
  `tegra-libraries-glescore`, `libglvnd`, and `tegra-nvsciipc`.
- Replace Hadron's CTI board DTB, SKU overlay, pinmux, and BCT inputs with
  corresponding assets from an official CTI R36.5 package for the Hadron NGX012
  and p3767-0003 module.
- Update Hadron version documentation only after successful build validation.
- Preserve other layer references, Hadron image contents, and board settings
  except for the explicit NVIDIA package additions and version/source updates.

Do not use Lumen-specific board files in place of CTI Hadron assets. Do not
flash the device as part of this work.

## Source gate

No matching CTI R36.5 NGX012 package was present in either repository or the
expected local L4T directory during design. The existing Hadron files come
from `CTI-L4T-ORIN-NX-NANO-36.4.4-V005`.

Implementation must not substitute those old binaries or infer compatibility.
Before changing the CTI recipe, confirm the vendor package provenance, target
board/SOM, and required files. If an official matching package cannot be
obtained, stop the upgrade and report the blocker; do not present a partial
`meta-tegra`/package-only change as a completed R36.5 board upgrade.

## Validation

1. Verify the CTI package is specifically for NGX012 / p3767-0003 and inspect
   the DTB, overlay, pinmux, and BCT files before replacing the recipe inputs.
2. Verify kas resolves the intended `meta-tegra` commit and BitBake parses the
   Hadron machine, CTI provider, and image recipes.
3. Build `hadron-image-base` and confirm the output targets L4T R36.5.0.
4. Inspect the rootfs package manifest to confirm all five requested NVIDIA
   packages are present.
5. Review the generated flash package's board-specific DTB/BCT provenance.
   Hardware flashing and runtime validation are separate, explicitly gated
   follow-up work.

## Alternatives considered

- Keep R36.4.4 and add packages only: lowest change risk, but not the requested
  L4T alignment.
- Move only the `meta-tegra` pin and reuse CTI 36.4.4 files: rejected because
  it assumes board-asset compatibility without an authoritative matching source
  or a new hardware validation.
- Match all Lumen layer revisions/configuration: rejected as unnecessary scope
  and greater compatibility risk.
